### Связь таблиц
* **Родительская таблица** содержит уникальный идентификатор (Primary Key).

* **Дочерняя таблица** (Зависимая) содержит внешний ключ (Foreign Key), который ссылается на родительскую таблицу, и хранит производные или связанные данные.

### Операции с таблицами

### DELETE
Удаление записи
* **`RESTRICT` (Ограничение)**  
  Запрещает удаление строки из родительской таблицы, если в дочерней таблице есть хотя бы одна связанная с ней строка.
  
* **`CASCADE` (Каскадное удаление)**  
  При удалении строки из родительской таблицы СУБД автоматически удаляет все связанные строки из дочерних таблиц.
  
* **`SET NULL` (Установка в NULL)**  
  Заменяет значение внешнего ключа в дочерней таблице на `NULL`, если связанная строка в родительской таблице была удалена. *Требует, чтобы для столбца не стояло ограничение `NOT NULL`.*

* **`NO ACTION` (Без действия / Отложенная проверка)**  
  По умолчанию ведет себя как `RESTRICT` и запрещает удаление родительской строки при наличии связанных дочерних. Однако, в отличие от `RESTRICT`, позволяет отложить проверку целостности на самый конец транзакции (`COMMIT`).


### UPDATE 
Обновление существующего значения 
* **`RESTRICT` (Ограничение)**  
  Запрещает обновление строки из родительской таблицы, если в дочерней таблице есть хотя бы одна связанная с ней строка.
  
* **`CASCADE` (Каскадное удаление)**  
  При обновлении строки из родительской таблицы СУБД автоматически обновляет все связанные строки из дочерних таблиц.
  
* **`SET NULL` (Установка в NULL)**  
  Заменяет значение внешнего ключа в дочерней таблице на `NULL`, если связанная строка в родительской таблице была обновлена. *Требует, чтобы для столбца не стояло ограничение `NOT NULL`.*

* **`NO ACTION` (Без действия / Отложенная проверка)**  
  По умолчанию ведет себя как `RESTRICT` и запрещает удаление родительской строки при наличии связанных дочерних. Однако, в отличие от `RESTRICT`, позволяет отложить проверку целостности на самый конец транзакции (`COMMIT`).

### INSERT
Добавление новых значений в таблицу
* **`RESTRICT` (Ограничение)**  
  Запрещает вставлять строку в дочернюю таблицу, если указанного идентификатора (ID) еще нет в родительской таблице.

* **`SET NULL` (Установка в NULL)**
    СУБД позволяет вставить строку в дочернюю таблицу с пустым внешним ключом (`NULL`).

* **`NO ACTION` (Без действия / Отложенная проверка)**  
    Позволяет временно вставить запись в дочернюю таблицу с указанием еще не существующего родительского ID. Проверка связи переносится на момент завершения транзакции (`COMMIT`), к которому родительская строка уже обязана быть создана.

## 19 Сентября. Практика
**Создание таблиц**
```sql
CREATE TABLE nam (
    u_id SERIAL PRIMARY KEY,
    n_val VARCHAR(50) NOT NULL
);

CREATE TABLE fam (
    u_id SERIAL PRIMARY KEY,
    f_val VARCHAR(50) NOT NULL
);

CREATE TABLE otc (
    u_id SERIAL PRIMARY KEY,
    o_val VARCHAR(50) NOT NULL
);

CREATE TABLE street (
    u_id SERIAL PRIMARY KEY,
    s_val VARCHAR(50) NOT NULL
);

CREATE TABLE people (
    u_id SERIAL PRIMARY KEY,
    fam INT REFERENCES fam(u_id),
    nam INT REFERENCES nam(u_id),
    otc INT REFERENCES otc(u_id),
    street INT REFERENCES street(u_id),
    bldn VARCHAR(5),
    bldn_k VARCHAR(5),
    appr INT,
    telef_n VARCHAR(30)
);
```
**Вывод объединённой таблицы**
```sql
SELECT people.u_id, fam.f_val, nam.n_val, otc.o_val, street.s_val, people.bldn, people.bldn_k, people.appr, people.telef_n
FROM people
    JOIN fam ON people.fam = fam.u_id
    JOIN nam ON people.nam = nam.u_id
    JOIN otc ON people.otc = otc.u_id
    JOIN street ON people.street = street.u_id
```  


**`cross join`** – перекрестное соединение
Возвращает все возможные комбинации сочетаний значений (декартово произведение).

| *table 1* | *table 2* |
| -- | -- |

| Петр | Петров|


```sql
SELECT n.name, s.surname
FROM name n
CROSS JOIN surname s ORDER BY n.name ASC
```

|------|---------|
| Иван | Иванов  |
| Иван | Петров  |
| Петр | Иванов  |

`Транзакция` – совокупность операций, которые должны либо выполнится успешно, либо не выполниться вовсе.  
**ACID**
* `Atomicity` – атомарность транзакций. Либо применяются все изменения, либо ни одного. 
* `Consistency` – транзакции не нарушают согласованность данных. То есть переводят бд из одного корректного состояние в другое. 
* `Isolation` – одновременные транзакции не влияют друг на друга. Многопоточно выполняются так же, как выполнились бы последовательно
* `Durability` – если транзакция была успешно применена, то внешнее воздействие не должно привести к потере изменений.

### ODBC (Open Database Connectivity) 
 **ODBC** – это универсальный API для доступа к базам данных, который позволяет программам работать с различными СУБД через единый набор команд.  

 ODBC нужен для того, чтобы отвязать код приложения от конкретной базы данных. Без него разработчикам пришлось бы писать отдельный код для взаимодействия с каждой СУБД. ### SELECT 
`SELECT` – запрос для получения данных, без их изменения. Может сочетаться с операторами для фильтрации. 
```sql
SELECT * {DISTINCT | ALL }
FROM {<имя таблицы>}, ...
[WHERE <предикат>]
[GROUP BY {<имя столбца> | <целое>}, ...]
[HAVING <предикат>]
[ORDER BY {<имя столбца> | <целое>}, ...]
```


| Часть	| Назначение| 
| -- | -- |
| `SELECT` | 	какие столбцы/выражения вернуть |
| `DISTINCT` | 	убрать полностью одинаковые строки результата |
| `ALL` | 	оставить все строки; используется по умолчанию |
| `FROM` | 	из каких таблиц брать данные |
| `WHERE` | 	фильтрация строк до группировки |
| `GROUP BY` |	разбиение строк на группы| 
| `HAVING` | 	фильтрация групп после группировки |
| `ORDER BY` | сортировка результата |

## WHERE, GROUP BY, HAVING

### WHERE
- Фильтрует **строки** до группировки.
- Нельзя использовать агрегатные функции (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`).
- Можно использовать `AND`, `OR`, `IN`, `BETWEEN`, `LIKE`, `IS NULL`.

**Пример `WHERE`**

```sql
SELECT *
FROM Students
WHERE age >= 17 AND group_id = 101;
```

**Результат:**
id | name | age | group_id
---|------|-----|---------
1  | Анна | 18  | 101
4  | Пётр | 17  | 101


### GROUP BY
- Группирует строки по одному или нескольким столбцам.
- Нужен для агрегатных функций.
- Если в SELECT есть неагрегированный столбец, он обычно должен быть в GROUP BY.

**Пример `GROUP BY`**
```sql
SELECT group_id, COUNT(*) AS cnt
FROM Students
GROUP BY group_id;
```

**Результат:**
group_id | cnt
---------|----
101      | 3
102      | 2
103      | 1

### HAVING

- Фильтрует группы после GROUP BY.
- Можно использовать агрегатные функции.
- Применяется после группировки, в отличие от WHERE.

**Пример `HAVING`**
```sql
SELECT group_id, COUNT(*) AS cnt
FROM Students
GROUP BY group_id
HAVING COUNT(*) > 10;
```
**Результат:**
group_id | cnt
---------|----
101      | 3

## INSERT
`INSERT` - добавление данных в таблицу
```sql
INSERT INTO [owner.]table-name [(column-name)] VALUES (expression)
```

```sql
INSERT INTO [owner.]table-name [(column-name)] ... select-statement
```
**Пример `INSERT`**
```sql
INSERT INTO Fam(fam_cod, fam_val) VALUES (123,'Склеймин')
```

Добавление сразу нескольких строк:
```sql
INSERT INTO Fam(fam_cod, fam_val) VALUES
    (124, 'Петров'),
    (125, 'Сидоров');
```

Если список столбцов не указан, значения задаются для **всех** столбцов в порядке их объявления в таблице:
```sql
INSERT INTO Fam VALUES (126, 'Смирнов');
```

Добавление данных из другого запроса:
```sql
INSERT INTO Fam(fam_cod, fam_val)
SELECT u_id, f_val FROM fam_backup;
```

> Столбцы, не указанные в `INSERT`, получают значение по умолчанию (`DEFAULT`) или `NULL`. Если для столбца задано ограничение `NOT NULL` и нет значения по умолчанию, вставка без него завершится ошибкой.
## UPDATE 
`UPDATE` - команда обновления значений столбцов

```sql
UPDATE table-list 
  SET column-name = expression, ... 
  [WHERE search-condition]
  [ORDER BY expression [ASC | DESC], ...]
```
если условие не выполнится - обновятся значения всех столбцов 

**Пример `UPDATE`**

Обновление одной строки:
```sql
UPDATE fam
SET fam_val = 'Склеймин'
WHERE fam_cod = 123;
```

Обновление нескольких столбцов сразу:
```sql
UPDATE people
SET telef_n = '8(800)555-35-35', appr = 111
WHERE u_id = 1;
```

Обновление всех строк (условие `WHERE` отсутствует):
```sql
UPDATE fam
SET fam_val = 'Иванов';
```

> `UPDATE` изменяет только существующие строки. Если строки под условие не попали — ничего не произойдёт, новые записи не добавятся (для этого нужен `INSERT`).

## DELETE 

```sql
DELETE [FROM] [owner.]table-name [FROM table-list] [WHERE search-condition]
```

если условие WHERE отсутствует, оно считается истинным  - удаляться все значения 

**Пример `DELETE`**
```sql
DELETE FROM fam WHERE fam_code=123
```

Удаление всех строк таблицы (условие отсутствует):
```sql
DELETE FROM fam;
```

> `DELETE` удаляет строки, но не саму таблицу. Для удаления таблицы целиком используется `DROP TABLE`, а для очистки без журналирования отдельных строк — `TRUNCATE TABLE`.

## Представления

`Представление` (view) — виртуальная таблица, сформированная на основе запроса `SELECT`. К ней можно обращаться как к отдельной таблице для извлечения данных. Сами данные в представлении не хранятся — хранится только описание запроса, который выполняется при каждом обращении.

**Синтаксис создания**
```sql
CREATE [OR REPLACE] VIEW [owner.]view-name [(column-name, ...)] AS
  select-statement
  [WITH CHECK OPTION]
```

**Пример `CREATE VIEW`**
```sql
CREATE VIEW people_view AS
SELECT people.u_id, fam.f_val AS fam, nam.n_val AS nam, otc.o_val AS otc,
       street.s_val AS street, people.bldn, people.bldn_k, people.appr, people.telef_n
FROM people
    JOIN fam ON people.fam = fam.u_id
    JOIN nam ON people.nam = nam.u_id
    JOIN otc ON people.otc = otc.u_id
    JOIN street ON people.street = street.u_id;
```

После создания к представлению обращаются как к обычной таблице:
```sql
SELECT * FROM people_view WHERE fam = 'Иванов';
```

**Зачем нужны представления**
* **Упрощение** — сложный запрос с множеством `JOIN` пишется один раз, а используется как простая таблица.
* **Безопасность** — можно скрыть часть столбцов или строк и выдать пользователю доступ только к представлению, а не к базовой таблице.
* **Совместимость** — при изменении структуры таблиц приложение продолжает работать через представление с прежним набором столбцов.
* **Логическая независимость** — представление может объединять данные из нескольких таблиц и даже из других представлений.

**Обновляемые представления**

Часть представлений допускает `INSERT`, `UPDATE` и `DELETE` — изменения автоматически переносятся в базовую таблицу. Представление обновляемо, если оно построено на одной таблице, не содержит `DISTINCT`, `GROUP BY`, `HAVING`, агрегатных функций и вычисляемых столбцов.

Представление только для чтения (read-only) на основе `JOIN` из примера выше менять нельзя.

`WITH CHECK OPTION` запрещает вставлять или изменять строки так, чтобы они переставали удовлетворять условию `WHERE` представления:
```sql
CREATE VIEW adult_students AS
SELECT * FROM Students WHERE age >= 18
WITH CHECK OPTION;
```

**Удаление представления**
```sql
DROP VIEW people_view;
```

> Представление не занимает места под данные и всегда показывает актуальное состояние базовых таблиц. Если нужен физически сохранённый результат запроса, используются материализованные представления (`CREATE MATERIALIZED VIEW`) с периодическим обновлением через `REFRESH MATERIALIZED VIEW`.
